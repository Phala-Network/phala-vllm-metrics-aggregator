# Four-replica metrics aggregation

This small Python service exposes authenticated GET/HEAD `/v1/metrics` on loopback port 30081. It fetches the four existing PIG `/v1/metrics` endpoints at 8200–8203 concurrently, using the existing `TOKEN`. PIG and router currently provide no native multi-replica diagnostics aggregation; HAProxy only selects a backend.

Each original sample gains `replica="0"` through `"3"`. Existing metric names, labels and numeric values remain intact. The output contains no additional pool totals: sum counters/gauges as appropriate in PromQL, calculate histogram quantiles after summing bucket rates, and keep summary quantiles per replica. `replica` is reserved; an upstream collision is an explicit error. Scrape this aggregate once per node; simultaneously ingesting its per-replica diagnostic endpoints into the same pool queries double-counts data.

The pinned `prometheus-client` parser validates individual samples. The merger rejects duplicate series, conflicting HELP/TYPE declarations and ambiguous families; emits each declaration once; keeps histogram/summary families contiguous; and translates Rust OpenMetrics counter declarations to Prometheus 0.0.4 `_total` declarations without renaming samples. OpenMetrics timestamps become integer milliseconds. Unsupported metric types/exemplars fail explicitly instead of being silently discarded.

One scrape runs at a time with four upstream workers, a 3-second fetch deadline, a 3.25-second collection wait, a 4 MiB/20,000-sample limit per upstream and at most eight inbound handlers. Proxy environment variables and redirects are disabled for credential-bearing requests. No response body, token or request headers are logged. Any failed/missing replica returns HTTP 503 JSON with `failed_replicas`; incompatible cross-replica schemas return HTTP 503 `incompatible_metrics`. No partial samples or stale cache are returned. A PIG HTTP 200 containing its backend-fetch-failure comment or no vLLM samples is also rejected. This deployment requires the pinned Rust backend's unique final OpenMetrics EOF marker and checks any HTTP Content-Length, rejecting syntactically valid but truncated prefixes. `/healthz` is local liveness, not a claim that all four sources are available.

Build from this directory. The [Dockerfile](Dockerfile) pins the official Python base digest and [requirements.txt](requirements.txt) pins the parser wheel hash; there are no runtime source mounts or package installs. Run `python -m unittest discover -s image-builds/metrics-aggregator` after installing the pinned requirements. Tests cover sample fidelity, metadata and labels, families, incomplete scrapes, bounded timeouts, authentication and HEAD. A real 111,340-byte PIG fixture also passed four-way merging with 1,055 series per replica; that operational fixture is kept outside the production source tree.

Publish source first under an immutable `metrics-aggregator-v<VERSION>` tag and a published GitHub Release. The release workflow tests and publishes `ghcr.io/phala-network/metrics-aggregator:<VERSION>` for linux/amd64. Record its registry digest and final-image checks before pinning it in production; a source commit or image publication alone does not establish target acceptance.
